# 优化设计与兼容性说明

## 研究结论

瓶颈不是缺少动画组件，而是现有组件、时间数据、指令和验证机制没有形成一致的制作流程。

研究覆盖两个模板的内容层与底层、全部主题和 fxkit、场景清单、图片来源、字幕/配音/重定时、资源同步、渲染、打包、QA、测试和 CI。保留 Remotion、原生 30fps、既有主题、字体、字幕外观和组件体系，不引入新的动画运行时或生图服务。

## 优先处理的问题

| 问题 | 处理方式 | 为什么这样做 |
|---|---|---|
| 强制多区域、图文双份讲解、指定技术组件，让视频容易变成卡片堆叠 | 主视觉解释一个动作，辅助区域按内容选择；少量组合配方代替组件配额 | 降低机械套模板，不用增加更多特效 |
| 图片默认生成与必须询问的规则冲突 | 统一能力检测、授权和原生绘图替代规则 | 不假设任何 Agent 必然有生图能力，也不把生图变成依赖 |
| 镜头切点、清单和章节 chrome 不一致 | 讲解模板从场景清单读取窗口、章节和局部帧 | 减少重复维护；语义动作仍须绑定新的配音 cue |
| 首尾和切换容易出现空白内容 | 去掉整场淡空后的间隙；保留干净切换；按半帧向上舍入保护语音尾部 | 黑帧扫描无法发现象牙色的空页面 |
| 分支任务不沿所画路径移动 | SVG 与运动读取同一组路径几何 | 运动表达过程，而不是贴在背景上的装饰 |
| 结尾技能卡长时间没有状态变化 | 在协助台词处激活状态，最后退出卡片留下 CTA | 动作和信息随叙事推进，不只在入场时动一下 |
| fxkit 在无 extras 的主题下导入即崩溃，退出参数覆盖入场 | 安全可选属性、稳定 hook 调用、只在退出阶段覆盖样式 | 让已有复用能力真正可用 |
| 原生 img 不等待加载，焦点缩放露空边 | 使用 Remotion Img、限制焦点变换、增加可配置语义节点 | 复用原来的图片组件，而不是另做媒体框架 |
| 缺少主视觉与辅助图片的连续组合 | 一个 EvidenceBridge 配方：图片由嵌图扩大、定位，再回到原处 | 单图单一归属，不改变旁白时间轴，不要求复杂双场景重叠 |
| 字幕实际字体、字重、间距与测量不同 | 在实际主题字幕组件里测量隐藏全文；使用对应画布宽度 | 不复制另一套容易过期的排版常量 |
| 原有 CardFitGate 可能晚于截图执行 | 字体就绪后阻塞当前帧，扫描结束才继续 | 让失败确实拦截输出，同时明确它不覆盖全部变换/遮挡 |
| classic 字幕在中文词连接时抛出 isHan.test 错误 | 移除额外造空格的逻辑，统一字幕 lead 与尾标点裁剪 | 静态“示例通过”并不等于旧模板真的能渲染 |
| TTS 混合采样率 WAV 直接拼接，章节时长失真 | 统一 PCM 格式后测量和拼接 | 先保证音频正确，再谈逐词视觉同步 |
| 更换风格/服务仍命中旧缓存，更换声线后无法定位当前片段 | 完整请求身份缓存、活动片段顺序清单和哈希 | 保留缓存收益，不混入过期声音 |
| 变速与换声后的章节间隔累计漂移 | 从锁定边界计算每段空隙，按样本补齐/裁剪 | 保留批准过的时间轴，不复用过期的固定 gap.wav |
| 无效字幕时间可通过校验；重定时失败后留下半份改动 | 严格时间类型/顺序/结束值检查，所有验证先于写入 | 不让两份相同的坏数据互相“证明正确” |
| 分析失败被当成零黑帧；固定临时文件存在并发冲突 | FFmpeg 失败即失败、检查接触片产物、独立原始渲染目录 | 可复现的错误不应被绿灯掩盖 |
| 源码 ZIP 泄漏环境配置、自我打包或丢失有效声音缓存 | 排除秘密和外部链接；临时归档后替换；保留活动/无歧义旧片段 | 交付必须同时安全和可编辑 |

## 刻意没有引入的系统

- 不建立不断增长的场景模板库，也不要求固定 A/B 比例。
- 不引入独立 beat 引擎、全片转场调度器、模型路由或生图 API。现有帧数据和 Remotion 足以支持当前配方。
- 不把 Framer/Motion 等浏览器时钟动画直接套进视频渲染。官方文档要求由帧驱动动画。
- 不盲目用 TransitionSeries 包装实测旁白片段：普通重叠转场会缩短总时间，必须另行显式规划。
- 不自动给“视频好看程度”打分。重复布局、缺少解释、变换后的遮挡和空白内容仍须看图判断。
- 不重写四主题美学，不改变 classic 的场景设计，不升级已经锁定的依赖版本。只将版本范围钉到现有 lockfile 中的 Remotion 4.0.489。

## 外部依据

从 Remotion 官方仓库文档核对了当前实现所依赖的行为：

- [Sequence 与局部帧](https://www.remotion.dev/docs/sequence)：场景嵌套时避免重复扣除开始帧。
- [帧驱动动画](https://www.remotion.dev/docs/animating-properties)：不用 CSS 时间动画替代可随机取帧的确定性动画。
- [Img 加载契约](https://www.remotion.dev/docs/img)：等待解码，缺失资源触发失败。
- [转场时长](https://www.remotion.dev/docs/transitions/)：重叠会缩短总时长。
- [性能建议](https://www.remotion.dev/docs/performance)：并发必须测量，少做重复加载和不必要的 GPU 效果。

上游文档可能包含比当前安装版更新的 API；本次配方只使用已安装版本具备的能力。

## 使用与迁移

1. 新工程仍由 `new-project` 创建，旧组件和 composition ID 保持可用。
2. 旧工程不会被自动覆盖。迁移底层修复时先备份；不要把新例子的场景窗口直接套到旧旁白。
3. 新项目先运行 `validate-project`，再用 `review-plan` 和 `review-frames` 检查实际关键帧。
4. 字幕精度必须注明：内置 TTS 适配器测量章节，但字级时间为估计，不能称为声学强制对齐。
5. ZIP 保留活动片段。旧缓存无歧义时兼容；有多个声线却没有活动清单时明确拒绝打包，避免悄悄选错或丢失可编辑素材。
6. `npm run render` 是原始预览；使用统一 launcher 做规范化交付并测量成片。
7. [测试说明](testing.md) 给出纯脚本、真实媒体和浏览器验证步骤及各自不能证明的事项。

入口 SKILL.md 从约 32.8KB 精简到约 14.1KB。这个数字是文件字节数，不是模型 Token 或制作时长的基准测试。专题说明仍按需保留。
