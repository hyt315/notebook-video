# 讲稿写法标准（组件路线与手作路线共用）

本篇只管一件事：**把一个知识点讲清楚、让观众记住并无负担看懂**。画面节奏见 [draftpaper.md](draftpaper.md)，导演层与结构族见 [director.md](director.md)，硬门禁见 [checks.md](checks.md)。

## 六条写作硬标准

1. **一支片子只讲清一件事，3–6 秒亮出核心承诺，不卖关子、不藏着结论**
   - 动笔前先用一句话定死本片的核心答案（≤20 字），任何无关背景史或旁枝概念一律删掉。
   - **区分「开场承诺（0–6s）」与「结论兑现」**：开场 0–6 秒用最强画面、反常证据或诚实的问题把「这支片子值不值得看、到底要弄清什么」摊开在桌上（组件直讲型在前两镜即点明核心方向；悬疑/发现结构族最晚于 80% 进度前揭晓机制并在结尾完整闭合，严禁标题党或假悬念收尾）。

2. **误解优先：用直觉冲突或反常事实开篇，禁止教科书定义**
   - 严禁用「XX 是一种常用的……」「今天我们来介绍……」开场；须在第一镜先摆出观众真会信错的直觉，或一个一眼矛盾的数字/现象，再用后续镜头实证拆解。

3. **每一镜只回答一个问题（`$asks`），相邻镜头构成问答链**
   - 在 `story.json` 每镜写明 `"$asks": "本镜回答哪个问题"`（蓝图已预置；未填记 P1）；若某镜只是重复上一镜或引不出下一问，直接删镜。

4. **案例具体到数字、物件或真实场景，同时控制信息不超载**
   - 禁用「某个系统」「提升明显」等空话，须写具体对比（例如「100 条订单敲了 101 次库，耗时 620ms → 14ms」）；单镜只担一问、画面 ≤40 字、台词 1–3 句，高信息密度后留 1 镜呼吸。

5. **术语首现配大白话口语翻译，写自然口语稿**
   - 专有名词首次出现须紧跟 ≤16 字大白话并配 `glossary` 或 `define`；台词写读得出口的自然中文（避免 raw 符号 `>=`、`!=`、`->` 或网址直进 `lines`，数字/单位写清口语读法），避免生硬机器腔或照搬图文。

6. **结尾闭合开场问题，留 1 句 ≤16 字的锤子句**
   - 最后一镜必须直接呼应第 1 镜抛出的问题或误区（禁泛泛升华）；全片留 2–3 个**锤子帧**，末句 ≤16 字以便复述。

## 节奏与事实边界

- **句长与读速**：每行字幕 ≤ `CAPTION_MAX_CHARS`（16，逐字 P0），由 `compose-story.py` 在语义与 `protect` 断点拆行；无配音排时长按 `READ_CPS`（4.5 加权字/秒，手作可 `--cps=6.5`），硬门禁上限 `CPS_MAX`（9.0）。
- **事实出处边界**：核心结论依赖的数字/年份/因果找不到可靠出处须**停下问用户**；次要背景缺出处记 P1；类比必须显式标 `"kind": "analogy"`（写进 `story.json` 顶层 `sources[]` 与镜上 `claim`，引用不存在来源或类比误挂来源判 P0；出片前跑 `validate-facts <工程> --review` 核对）。

## 好讲稿 vs 坏讲稿对照

### 对照 1：布隆过滤器（组件路线 · 概念题）

- **坏**：> S1：布隆过滤器是一种常用数据结构，在很多系统里判断存在。 / S2：它由位数组和哈希函数组成。 / S6：总结一下，它很省内存，工程里用处很大。（定义先行、空泛口号）
- **好**：
  > S1（`$asks`：为什么不用哈希表直接存十亿网址？）：拦截十亿个恶意网址，哈希表吃 40GB，布隆过滤器只占 1.2GB。它凭什么省掉九成空间？
  > S2（`$asks`：不存原网址，到底存什么？）：答案是它根本不存网址本身，只留一排初值为 0 的开关格子，叫位数组。
  > S6（`$asks`：只记一句话该记什么？）：记住这句：亮灯未必在，熄灯一定不在——这就是 1.2GB 守住十亿网址的秘密。

### 对照 2：消除 SQL N+1 慢查询（组件路线 · 代码改动题）

- **坏**：> S1：接口慢常见原因是 N+1 查询。 / S4：SQL 从 101 次降到 2 次，明显更快。 / S5：注意使用 IN 批量提升性能。（缺具体痛感与数字对照）
- **好**：
  > S1（`$asks`：三行干净代码为何拖垮接口？）：三行循环查单看着干净，一页 100 条订单却偷偷敲了数据库 101 次门，拖出 620 毫秒。
  > S4（`$asks`：改成 IN 批量到底快多少？）：101 次往返压成 2 次，耗时从 620 毫秒掉到 14 毫秒，快了四十多倍。
  > S5（`$asks`：怎么一眼避开？）：循环里别查库，攒齐编号一次拿——三行不动逻辑，省下 99 次空跑。

### 对照 3：天空为什么不是紫色的（手作路线 · 为什么题）

- **坏**：> S1：晴天呈现蓝色，背后是什么原理？ / S2：大气对短波瑞利散射更强。 / S5：这是物理与生理共同作用的结果。（开场讲人所共知、结尾抽象）
- **好**：
  > S1（`$asks`：紫光散射明明比蓝光更强，晴天为什么不是紫的？）：短波更容易被散射，紫光比蓝光更短、散射更猛，可抬头为什么不是一片紫天？
  > S2（`$asks`：空气分子怎么拆开阳光？）：阳光撞上微小的空气分子会像弹珠撞细网一样弹开——这就是瑞利散射，波越短弹得越散。
  > S5（`$asks`：蓝天到底谁决定？）：大气本来把天洒成蓝紫混合，是人眼把紫色调暗——你看到的蓝，是太阳、空气与眼睛共同调色。

## 讲稿自查清单

按 [rubric.md](rubric.md) 5 项 1–5 分核对：1）能否一句话复述核心机制；2）是否先打掉真实误解；3）例子/隐喻是否专属于本题；4）画面节奏与景别是否替观众卸载负荷而非模板复刻；5）是否有记得住且闭合首问的锤子句。
